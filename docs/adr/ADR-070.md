# ADR-070. Уникальность псевдонима — индексом БД, без проверочных запросов

- **Дата:** 2026-11-05 (этап 11)
- **Статус:** изменено [ADR-072](ADR-072.md) (цикл повтора убран, индекс остается)

По просьбе владельца: два игрока не могут иметь один псевдоним, и система не должна постоянно спрашивать базу «свободно ли имя». Решение: частичный уникальный индекс `profiles_display_name_unique` по `lower(display_name)` для неудаленных профилей (у удаленных общее «Удалённый игрок»; `deleted_at` выставляется тем же UPDATE, что и имя). `generate_pseudonym()` ничего не читает из таблиц. `ensure_user_initialized` читает профиль одним запросом по первичному ключу (он нужен и для проверки блокировки): у существующего профиля вставки и генерации нет совсем, то есть при повторных входах запросов стало меньше. Для нового профиля вставка выполняется сразу; при конфликте имени (`unique_violation` на этом индексе) — повтор с новым именем, не больше 10 раз, потом ошибка; конфликт по первичному ключу означает, что профиль уже создал параллельный вызов, повтор не нужен. Гонку двух одновременных вызовов решает сам индекс. Миграция при применении один раз переименовывает существующие профили с повторяющимися и не-псевдонимными именами. Альтернативы: проверка `exists` перед вставкой (лишний запрос и гонка), последовательность с взаимно однозначным преобразованием номера в имя (без повторов, но имена предсказуемы и пространство конечно). Последствие: пространство 16×16×10 000 ≈ 2,56 млн имен; при тысячах игроков конфликты редки, при сотнях тысяч расширять списки слов или число цифр. Запрос на смену `display_name` с занятым значением вернет 23505 (экрана смены имени пока нет). **Цикл повтора при конфликте имени убран в [ADR-072](ADR-072.md): имя вводит пользователь, конфликт возвращается ему как «имя занято»; индекс остается.**
