# ADR-065. Согласия — отдельные документы и журнал-доказательство

- **Дата:** 2026-11-05 (этап 11)
- **Статус:** частично отменено [ADR-076](ADR-076.md) и [ADR-077](ADR-077.md)

_(Часть про согласие на публикацию отменена [ADR-076](ADR-076.md); отметки заменены подписью под кнопкой — [ADR-077](ADR-077.md).)_ С 01.09.2025 согласие на обработку ПДн оформляется отдельным документом, а раскрытие имени неограниченному кругу (рейтинг) требует ещё одного отдельного согласия (ст. 10.1 152-ФЗ). Поэтому при входе три отметки, по умолчанию сняты: «условия и 18+» и «обработка ПДн» обязательны, «публикация в рейтинге» нет. Выбор уходит в короткую httpOnly-cookie `divan_consent` (путь `/auth`, 600 с, значение `<LEGAL_VERSION>.<0|1>`), сессия без нее не создаётся; запись делает `/auth/callback` через `record_consents`. Журнал `user_consents` только добавляется (триггер, errcode 55000, как `wallet_entries`), запись идемпотентна (`consent_append`), содержит вид согласия, версию документа, `granted`, время. Версия — `LEGAL_VERSION` (дата), её формат проверяет БД. Рейтинг показывает только игроков, у которых последняя запись PUBLICATION имеет `granted = true`; отзыв — `/my/account` и `POST /api/v1/me/consents` (лимит 10/мин). `delete_my_account()` пишет отзыв всех действующих согласий. Альтернатива «одна галочка на всё» отклонена: не соответствует требованию об отдельном документе. Последствие: пользователи, вошедшие до миграции, не видны в рейтинге до следующего входа; принудительного повторного согласия при смене версии пока нет.
