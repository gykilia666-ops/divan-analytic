# ADR-075. Профиль и кошелек создаются только при выборе псевдонима

- **Дата:** 2026-11-05 (этап 11)
- **Статус:** принято

По просьбе владельца: «нельзя засорять БД мусорными аккаунтами». Раньше вход через GitHub сразу создавал профиль, кошелек и начислял 10 000 монет (`ensure_user_initialized`); у каждого, кто вошел и ушел, оставались строки в `profiles`, `wallets`, `wallet_entries`. Миграция 20261118000001: (1) `ensure_user_initialized` удалена; `/auth/callback` только обменивает код и пишет согласия (`record_consents`), затем ведет на `/my/pseudonym`, если профиля или имени нет; (2) `set_pseudonym` в одной транзакции создает профиль с именем, кошелек и `INITIAL_CREDIT` (повторный вызов ничего не начисляет; параллельные вызовы одного пользователя идут по очереди через `pg_advisory_xact_lock`, конфликт имени решает уникальный индекс [ADR-070](ADR-070.md) — `NAME_TAKEN` и ничего не создается); профиль без имени от прежней схемы дозаполняется; учетная запись входа с `auth.users.deleted_at` профиль не получает (`ACCOUNT_NOT_FOUND`); (3) `user_consents` и `audit_events` теперь ссылаются на `auth.users`, а не на `profiles`: согласие фиксируется при входе, когда профиля еще нет (персональные данные GitHub у сервиса аутентификации обрабатываются с этого момента, доказательство согласия нужно сразу); `record_consents`, `set_publication_consent`, `delete_my_account` работают без профиля (удаление без профиля: отзыв согласий и запись в аудит, профиль не создается; повтор — по записи аудита); (4) `place_bet`: нет профиля -> `PSEUDONYM_REQUIRED`. Интерфейс: `requirePseudonym` и страница матча отправляют вошедшего без профиля на выбор имени; шапка у него показывает только «Выбрать псевдоним» и «Выйти»; `/my/account` доступна без профиля (выход, согласия, удаление словом «удалить»); `/api/v1/me` отдает `displayName: null`; страница входа ведет вошедшего без имени на `/my/pseudonym`. Что остается у сервиса для вошедшего и ушедшего: строка `auth.users` (создает Supabase, без нее вход невозможен) и три записи согласий — это осознанно ([ADR-065](ADR-065.md)). Альтернатива: хранить согласия в cookie до выбора имени (отклонена: теряется при истечении cookie и ослабляет доказательство). Последствие: стартовые монеты получает только тот, кто выбрал имя; сброс имени оператором ([ADR-073](ADR-073.md)) оставляет профиль и кошелек.
