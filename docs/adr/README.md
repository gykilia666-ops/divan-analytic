# Архитектурные решения (ADR)

Одно решение — один файл `ADR-NNN.md`. Решения не удаляются и не переписываются задним числом: если
решение пересмотрено, создается новое ADR, а у старого меняется статус. «§N» — раздел
[требований](../requirements.md). Пометка «по просьбе владельца» означает продуктовое решение владельца
проекта.

Новое решение — по [шаблону](template.md): дата, проблема, решение, альтернативы, последствия.

## Заметки к этапам

Проверенные факты, ограничения и отложенные задачи, записанные вместе с решениями.

### Этап 0 (2026-10-26)

Проверено по первоисточникам (football-data.org: pricing, coverage, policies, overtime; Vercel: cron, function limits; Supabase: pricing).

- **Подтверждённые ограничения:** Vercel Hobby cron — не чаще раза в сутки (подтверждает [ADR-005](ADR-005.md)); maxDuration на Hobby 300 с; free-функции в регионе `iad1` по умолчанию — регион выбрать по измеренной задержке до БД на этапе 11; Supabase Free — пауза после недели неактивности, без автоматических бэкапов, 2 активных проекта.
- **Открытый вопрос:** считается ли периодический запрос pg_cron/pg_net активностью, предотвращающей паузу Free-проекта, в документации не найдено. Проверить на этапе 7/11 и описать в runbook.

### Этап 2 (2026-11-02)

- **Отложено:** генерация типов БД (`supabase gen types`). В Windows PowerShell 5 оператор `>` пишет файл в UTF-16, поэтому вывод нужно сохранять через `Out-File -Encoding utf8` или Node-скрипт; сделать в начале этапа 3, когда код впервые обратится к БД.

### Этап 3 (2026-11-02)

Проверено по документации Supabase SSR: в Next.js 16 файл `middleware.ts` переименован в `proxy.ts`; для решений о доступе на сервере используется `getClaims()` (проверяет подпись токена), а не `getSession()`.

- **Не сделано в этапе 3:** браузерный Supabase-клиент (не нужен, пока нет клиентских подписок), генерация типов БД, rate limiting входа (действуют лимиты Supabase Auth), `/api/v1/me/wallet` и остальные `/me/*` (этапы 6–8).

### Этап 4 (2026-11-04)

Факты из запроса с токеном владельца (`scripts/probe-football-data.mjs`, 2026-11-04): токен видит 13 соревнований, из них 12 `TIER_ONE` (бесплатные) и `CLI` (`TIER_FOUR`); PL = 2021, BL1 = 2002, PD = 2014; `GET /competitions/{code}/matches?dateFrom&dateTo` с окном 10 дней возвращает матчи текущего сезона; у предстоящих матчей статус `TIMED`; `score.duration = REGULAR`, `fullTime` с null до начала; заголовки `X-Requests-Available-Minute` и `X-RequestCounter-Reset` (окно 60 с).
