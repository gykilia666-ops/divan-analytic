# ADR-073. Псевдоним выбирается один раз и не меняется

- **Дата:** 2026-11-05 (этап 11)
- **Статус:** принято

По просьбе владельца: «удали функцию сменить псевдоним, его можно создать только единоразово». Миграция 20261116000001 заменяет `set_pseudonym`: если имя уже выбрано, функция возвращает `ALREADY_SET` (HTTP 409) и ничего не пишет; повтор того же самого имени (двойной клик, повторная отправка) проходит как успех без записи. Проверка стоит до лимита попыток, поэтому у игрока с именем лимит не расходуется. Правило держится в БД, а не в интерфейсе: прямой UPDATE `display_name` у `authenticated` закрыт ([ADR-072](ADR-072.md)), функция — единственный путь. `/my/pseudonym` для игрока с именем перенаправляет на `next` или `/my/account`; на странице и в форме нет ветки «сменить», перед сохранением написано, что выбор одноразовый; ссылка «Сменить псевдоним» из `/my/account` убрана, вместо нее — обращение к оператору. Сбросить имя может только оператор из-под сервисной роли: `update public.profiles set display_name = null where id = '…'` (нарушение правил или просьба пользователя, 152‑ФЗ: уточнение данных по требованию субъекта) — после этого игрок выбирает имя заново (runbook). Освобождение имени: оно остается занятым, пока профиль не удален или не сброшен. Альтернативы: оставить смену с ограничением (раз в N дней) — отклонено владельцем; запретить смену только в интерфейсе — отклонено, обошлось бы прямым вызовом RPC. Последствие: опечатка в имени исправляется только через оператора или удаление аккаунта.
