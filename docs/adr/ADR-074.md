# ADR-074. Без псевдонима прогноз не принимается

- **Дата:** 2026-11-05 (этап 11)
- **Статус:** изменено [ADR-075](ADR-075.md) (профиль и кошелек создаются при выборе псевдонима)

По просьбе владельца: «система не должна давать пользователю права на создание прогноза, пока его данные не прошли валидацию; нельзя создать аккаунт без связки GitHub — псевдоним». Миграция 20261117000001 заменяет `place_bet`: после проверки аккаунта (`ACCOUNT_NOT_READY`, `ACCOUNT_DISABLED`) и до повторов, лимита частоты и блокировок рынка/кошелька функция проверяет `profiles.display_name`; если он NULL — `{ok:false, code:'PSEUDONYM_REQUIRED'}` (HTTP 403, сообщение «Сначала выберите псевдоним…»). Ничего не пишется, лимит не расходуется. Правило в БД, а не в интерфейсе: прямой вызов RPC с токеном его не обходит; создавать прогнозы мимо `place_bet` клиентским ролям нельзя (RLS/GRANT). Интерфейс: на странице матча вместо купона у вошедшего игрока без имени ссылка «выберите псевдоним» (возврат на матч), `bet-panel.tsx`; тексты `/my/pseudonym`, `/my/account`, политики. Связка «GitHub — псевдоним»: профиль привязан к `auth.users` по UUID (FK), псевдоним один и неизменный ([ADR-073](ADR-073.md)), уникальный ([ADR-070](ADR-070.md)); что вход возможен только через GitHub, обеспечивает настройка Supabase (Email выключен, `docs/deploy.md`), а не код БД. Начальные 10 000 монет по-прежнему выдаются при первом входе (`ensure_user_initialized`), но до выбора псевдонима потратить их нельзя и кошелёк недоступен (`requirePseudonym`). Альтернативы: создавать профиль и кошелёк только при выборе псевдонима (отклонено как более рискованная переделка инициализации и 10 тестов; можно сделать отдельным шагом); проверка только в API/интерфейсе (отклонена: обходится прямым вызовом RPC). Последствие: игрок, которому оператор сбросил имя ([ADR-073](ADR-073.md)), снова не может делать прогнозы, пока не выберет имя; уже сделанные прогнозы сохраняются.
