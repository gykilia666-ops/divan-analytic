# 09. Роли и права доступа

## Роли

| Роль                    | Как определяется                                                     | Где проверяется                                                      |
| ----------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Гость                   | нет сессии                                                           | сервер (страницы, API), БД (роль `anon`)                             |
| Вошедший без псевдонима | есть сессия, нет профиля                                             | сервер (`requirePseudonym`), БД (`place_bet` → `PSEUDONYM_REQUIRED`) |
| Игрок                   | есть профиль с псевдонимом, не отключен                              | сервер, БД (RLS по `auth.uid()`)                                     |
| Администратор           | игрок с записью `ADMIN` в `user_roles` и неотключенным профилем      | БД (`is_admin()` внутри каждой админ-функции)                        |
| Расписание              | запрос с верным `CRON_SECRET`                                        | сервер (сравнение постоянного времени)                               |
| Задание (система)       | серверный код с service role — только внутри конвейера синхронизации | сервер                                                               |
| Оператор (владелец)     | доступ к Supabase Dashboard и SQL                                    | вне приложения; действия — по runbook                                |

Роль администратора не берется из профиля, метаданных GitHub или cookie (BRL-26). Интерфейс скрывает
недоступное, но права всегда проверяются на сервере и в БД: прямой вызов API или RPC не обходит проверку.

## Доступ к данным (RLS и права)

| Таблица                                                               | anon   | authenticated                | Запись                                                                             |
| --------------------------------------------------------------------- | ------ | ---------------------------- | ---------------------------------------------------------------------------------- |
| `competitions`, `teams`, `matches`, `markets`                         | чтение | чтение                       | только функции синхронизации (service role)                                        |
| `profiles`                                                            | ⛔     | чтение своего                | только функции (`set_pseudonym`, `delete_my_account`)                              |
| `wallets`, `wallet_entries`, `bets`                                   | ⛔     | чтение своего                | только функции (`set_pseudonym`, `place_bet`, `settle_market`, `admin_compensate`) |
| `user_roles`                                                          | ⛔     | ⛔                           | оператор                                                                           |
| `user_consents`                                                       | ⛔     | свое — через `my_consents()` | `record_consents`, `delete_my_account`                                             |
| `audit_events`, `job_*`, `provider_rate_limits`, `rate_limit_buckets` | ⛔     | ⛔                           | функции и service role                                                             |

Общие правила:

- RLS включен на всех таблицах `public`; у клиентских ролей нет INSERT, UPDATE и DELETE ни на одну таблицу
  (проверяется тестом `10_hardening`).
- Функции, меняющие деньги и права, — SECURITY DEFINER с фиксированным `search_path` и проверкой пользователя
  внутри; служебные функции (`settle_market`, `admin_assert`, `leaderboard_ranked`) не выданы ни одной клиентской
  роли.
- Публичный рейтинг — отдельная функция с безопасным набором полей (BRL-24).

## Защита HTTP

| Мера                                                                                | Где                                                      |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Проверка `Origin` = `APP_ORIGIN` у всех изменяющих запросов                         | маршруты `POST`/`DELETE`, `/auth/login`, `/auth/signout` |
| Секрет расписания со сравнением постоянного времени                                 | `/api/internal/jobs/sync`                                |
| CSP с nonce на каждый ответ, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy` | `proxy.ts`, `next.config.ts`                             |
| Ограничение размера тела, строгие схемы входа                                       | маршруты API                                             |
| Безопасный адрес возврата после входа                                               | `safeNextPath`                                           |
| Очистка логов от токенов, cookie, почты                                             | `logEvent`                                               |
| `Cache-Control: no-store` у приватных ответов                                       | все личные маршруты                                      |
