# 05. Пользовательские истории и критерии приемки

Формат: «Как <роль>, я хочу <действие>, чтобы <ценность>». Критерии приемки — Gherkin (Дано / Когда / Тогда).
Оценка — story points (1, 2, 3, 5, 8) по сложности относительно истории US-07 = 3.

## Эпики

| Эпик                      | Истории      | Ценность                                      |
| ------------------------- | ------------ | --------------------------------------------- |
| E1. Вход и псевдоним      | US-01…04     | войти без лишних данных и анонимно            |
| E2. Матчи                 | US-05, US-06 | найти матч и понять, можно ли сделать прогноз |
| E3. Прогнозы и кошелек    | US-07…10     | поставить монеты и доверять учету             |
| E4. Расчет                | US-11…13     | узнать результат без участия человека         |
| E5. Статистика и рейтинг  | US-14, US-15 | сравнить себя с другими                       |
| E6. Аккаунт и приватность | US-16, US-17 | контролировать свои данные                    |
| E7. Администрирование     | US-18…20     | понимать и чинить задержки                    |
| E8. Demo и портфолио      | US-21, US-22 | показать продукт без ключей                   |

## E1. Вход и псевдоним

**US-01. Вход через GitHub** (3 SP, Must) — Как гость, я хочу войти через GitHub, чтобы не заводить пароль.

```gherkin
Сценарий: успешный вход нового пользователя
  Дано данные оператора заданы
  Когда гость нажимает «Войти через GitHub» и подтверждает доступ на GitHub
  Тогда создается сессия
  И в журнал согласий записаны согласие с условиями (18+) и на обработку ПДн текущей версии
  И пользователь попадает на страницу выбора псевдонима

Сценарий: данные оператора не заданы
  Дано не задано ФИО или почта оператора
  Когда гость открывает страницу входа
  Тогда видит «Вход временно недоступен» с причиной и не может начать вход

Сценарий: запрос входа с чужого сайта
  Когда POST /auth/login приходит с Origin, отличным от адреса сайта
  Тогда ответ 403 и перехода на GitHub нет
```

**US-02. Согласие без галочек** (1 SP, Must) — Как гость, я хочу видеть под кнопкой, с чем соглашаюсь, чтобы
вход не превращался в анкету.

```gherkin
Сценарий: подпись под кнопкой
  Когда гость открывает страницу входа
  Тогда под кнопкой есть ссылки на Соглашение, Согласие на обработку ПДн и Политику
  И текст, что нажатие означает согласие и подтверждение возраста 18+
```

**US-03. Выбор псевдонима** (5 SP, Must) — Как вошедший пользователь, я хочу придумать псевдоним, чтобы в
рейтинге не было моего имени и логина GitHub.

```gherkin
Сценарий: допустимое свободное имя
  Дано пользователь вошел и не выбрал псевдоним
  Когда он вводит «Тихий Форвард» и нажимает «Выбрать псевдоним»
  Тогда создаются профиль и кошелек
  И баланс равен 10 000, в журнале одна запись «Стартовые монеты»

Сценарий: имя совпадает с логином GitHub
  Когда пользователь вводит свой логин GitHub
  Тогда видит отказ «совпадает с данными GitHub», профиль не создан

Сценарий: имя занято без учета регистра
  Дано псевдоним «Тихий Форвард» есть у другого игрока
  Когда пользователь вводит «тихий форвард»
  Тогда видит «имя занято»

Сценарий: двойная отправка формы
  Когда одно и то же имя отправлено дважды подряд
  Тогда профиль один и стартовые монеты начислены один раз
```

**US-04. Псевдоним не меняется** (2 SP, Must) — Как владелец, я хочу, чтобы псевдоним выбирался один раз,
чтобы игроки не скрывали историю сменой имени.

```gherkin
Сценарий: попытка сменить имя через API
  Дано у игрока есть псевдоним
  Когда он отправляет POST /api/v1/me/pseudonym с другим именем
  Тогда ответ 409 ALREADY_SET и имя не меняется
```

## E2. Матчи

**US-05. Каталог** (5 SP, Must) — Как игрок, я хочу видеть предстоящие матчи с коэффициентами в своем часовом
поясе, чтобы выбрать, на что сделать прогноз.

```gherkin
Сценарий: каталог по умолчанию
  Когда пользователь открывает «Матчи» без параметров
  Тогда видит предстоящие матчи от ближайшего
  И время начала в зоне браузера с подписью зоны

Сценарий: фильтр по лиге и дате
  Когда выбраны «Premier League» и дата 2026-11-08 в зоне Asia/Novosibirsk
  Тогда показаны только матчи АПЛ, начинающиеся в эти сутки по Новосибирску
```

**US-06. Состояние приема** (3 SP, Must) — Как игрок, я хочу видеть, почему прогноз на матч недоступен.

```gherkin
Сценарий: до начала меньше 5 минут
  Дано до начала матча 3 минуты
  Тогда на карточке «Прием закрыт» и купона нет

Сценарий: данные устарели
  Дано матч не обновлялся больше 60 минут
  Тогда показано предупреждение об устаревших данных и прием закрыт
```

## E3. Прогнозы и кошелек

**US-07. Сделать прогноз** (3 SP, Must) — Как игрок, я хочу выбрать исход и сумму и сразу видеть возможную
выплату.

```gherkin
Сценарий: принятый прогноз
  Дано у игрока 10 000 монет и прием на матч открыт, коэффициент на победу хозяев 2.00
  Когда игрок выбирает «Победа хозяев», сумму 100 и подтверждает
  Тогда видит «Прогноз принят», баланс 9 900
  И возможная выплата 200 монет

Сценарий: не хватает монет
  Дано баланс 50
  Когда игрок подтверждает прогноз на 100
  Тогда видит «Недостаточно монет», баланс не изменился
```

**US-08. Двойной клик и повтор безопасны** (5 SP, Must) — Как игрок, я хочу, чтобы повтор при плохой сети не
списал монеты дважды.

```gherkin
Сценарий: двойной клик
  Когда игрок дважды быстро нажимает «Подтвердить прогноз»
  Тогда в базе один прогноз и одна запись списания

Сценарий: повтор того же запроса
  Дано прогноз принят по ключу K
  Когда клиент повторяет запрос с ключом K и теми же данными
  Тогда ответ 200 с replay = true и второго списания нет
```

**US-09. Коэффициенты изменились** (3 SP, Must)

```gherkin
Сценарий: устаревшая версия котировки
  Дано игрок открыл купон при версии 1, а рынок обновился до версии 2
  Когда игрок подтверждает прогноз
  Тогда видит «Коэффициенты изменились» и новые значения, монеты не списаны
```

**US-10. Кошелек и история** (3 SP, Must) — Как игрок, я хочу видеть все операции с монетами и свои прогнозы со
статусами.

```gherkin
Сценарий: журнал совпадает с балансом
  Тогда сумма операций в «Кошельке» равна балансу
  И у каждой операции есть вид, дата и сумма со знаком

Сценарий: фильтр истории
  Когда игрок выбирает статус «Выигрыш»
  Тогда видит только выигравшие прогнозы с результатом матча и выплатой
```

## E4. Расчет

**US-11. Автоматический расчет** (8 SP, Must) — Как игрок, я хочу получать выплату после матча без участия
человека.

```gherkin
Сценарий: подтвержденная победа хозяев
  Дано прогноз 100 на победу хозяев с коэффициентом 2.00
  И поставщик дважды с интервалом 11 минут сообщил счет 2:0
  Когда выполняется задание
  Тогда прогноз «Выигрыш», выплата 200, в журнале одна запись «Выигрыш»

Сценарий: повторный расчет
  Когда задание выполняется еще раз
  Тогда начислений больше нет
```

**US-12. Возвраты** (3 SP, Must)

```gherkin
Сценарий: матч отменен
  Дано отмена матча подтверждена
  Тогда прогнозы «Возврат», сумма каждого вернулась

Сценарий: матч прерван и не доигран
  Дано матч прерван и прошло больше 48 часов от начала
  Тогда прогнозы «Возврат»
```

**US-13. Спорный итог не угадывается** (5 SP, Must)

```gherkin
Сценарий: технический результат
  Дано поставщик сообщил статус AWARDED
  Тогда итог неоднозначен и прогнозы остаются «Ожидает результата»

Сценарий: итог изменился после расчета
  Дано рынок рассчитан по счету 2:1, а поставщик подтвердил 1:1
  Тогда матч на паузе, в аудите одна запись, начисленное не списано
```

## E5. Статистика и рейтинг

**US-14. Личная статистика** (3 SP, Must)

```gherkin
Сценарий: формулы
  Дано 3 выигрыша и 2 проигрыша по 100 монет с выплатами 200
  Тогда рассчитано 5, win rate 60,0 %, чистый результат +100, ROI 20,0 %

Сценарий: нет рассчитанных
  Тогда win rate и ROI «—»
```

**US-15. Публичный рейтинг** (5 SP, Must)

```gherkin
Сценарий: допуск
  Дано у игрока 4 рассчитанных прогноза
  Тогда его нет в рейтинге, а в статистике «до рейтинга осталось 1»

Сценарий: равный результат
  Дано у двух игроков одинаковый чистый результат, у первого 6 рассчитанных, у второго 5
  Тогда первый выше

Сценарий: безопасный ответ
  Когда запрашивается GET /api/v1/leaderboard
  Тогда в элементах только место, псевдоним, аватар (пустой) и итоговые числа
```

## E6. Аккаунт и приватность

**US-16. Удаление аккаунта** (5 SP, Must)

```gherkin
Сценарий: удаление
  Дано игрок «Тихий Форвард» с прогнозами
  Когда он вводит свой псевдоним и нажимает «Удалить аккаунт навсегда»
  Тогда он выходит из аккаунта
  И профиль называется «Удалённый игрок», его нет в рейтинге
  И журнал денег и прогнозы сохранены, баланс равен сумме журнала
  И повторный вход через GitHub создает новый аккаунт
```

**US-17. Документы** (3 SP, Must)

```gherkin
Сценарий: подвал
  Тогда на каждой странице есть ссылки на Соглашение, Политику, Согласие, отметка 18+ и дисклеймер
```

## E7. Администрирование

**US-18. Причина задержки расчета** (5 SP, Should)

```gherkin
Сценарий: итог ждет подтверждения
  Дано матч завершен, итог впервые увиден в 14:00
  Когда администратор открывает /admin
  Тогда матч в очереди «Итог ждет подтверждения», ожидается в 14:10
```

**US-19. Ручной запуск** (3 SP, Should)

```gherkin
Сценарий: лимит
  Дано администратор запускал синхронизацию 2 минуты назад
  Когда он нажимает «Запустить синхронизацию»
  Тогда видит «не чаще раза в 5 минут», задание не запущено
```

**US-20. Админка скрыта** (2 SP, Must)

```gherkin
Сценарий: обычный пользователь
  Когда игрок без роли открывает /admin
  Тогда ответ 404
  И POST /api/admin/sync отвечает 403
```

## E8. Demo и портфолио

**US-21. Demo без ключей** (3 SP, Must)

```gherkin
Сценарий: запуск
  Дано чистая копия репозитория без .env
  Когда разработчик выполняет npm ci и npm run dev
  Тогда сайт открывается с плашкой «ДЕМО-РЕЖИМ», матчами и демо-рейтингом
```

**US-22. Тема и фон** (2 SP, Could)

```gherkin
Сценарий: ночная тема сохраняется
  Когда пользователь включает «Ночь» и перезагружает страницу
  Тогда тема ночная без мигания

Сценарий: уменьшение движения
  Дано в системе включено «уменьшить движение»
  Тогда фон не смещается при прокрутке
```
