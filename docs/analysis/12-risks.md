# 12. Риски, допущения, открытые вопросы

## Реестр рисков

Вероятность и влияние: В — высокая, С — средняя, Н — низкая.

| ID   | Риск                                                                                         | Вер. | Вл. | Мера                                                                                                                           | Владелец      | Статус                 |
| ---- | -------------------------------------------------------------------------------------------- | ---- | --- | ------------------------------------------------------------------------------------------------------------------------------ | ------------- | ---------------------- |
| R-01 | Поставщик изменит формат ответа или статусы                                                  | С    | В   | явный маппинг, неизвестное отбрасывается; контрактный тест на сохраненном ответе; план — еженедельная проверка формата         | разработка    | открыт (мера частично) |
| R-02 | Поставщик недоступен или превышен лимит                                                      | С    | С   | бюджет 8/мин, пауза по 429, `PARTIAL` без потери данных, прием закрывается при данных > 60 мин                                 | разработка    | закрыт мерой           |
| R-03 | Ошибка итога у поставщика                                                                    | Н    | В   | подтверждение вторым наблюдением через 10 мин; конфликт после расчета — пауза и ручной разбор; компенсация новой записью       | администратор | закрыт мерой           |
| R-04 | Двойные списания или выплаты при повторах и гонках                                           | С    | В   | транзакции в БД, ключ повтора, уникальные ключи операций, аренда с поколением; интеграционные и e2e тесты                      | разработка    | закрыт мерой           |
| R-05 | Бесплатный проект Supabase «засыпает» без активности                                         | С    | С   | задание каждые 15 мин поддерживает активность                                                                                  | эксплуатация  | закрыт мерой           |
| R-06 | Неизвестно, что Supabase стирает при мягком удалении учетной записи (почта, identities)      | С    | С   | проверить после первого удаления в production; при необходимости дочищать вручную по runbook                                   | владелец      | открыт                 |
| R-07 | Юридические тексты подготовлены без юриста                                                   | В    | В   | тексты описывают фактическое поведение; чек-лист рисков; показать юристу до публичного запуска                                 | владелец      | открыт                 |
| R-08 | Вход только через GitHub — риск по новой ст. 13.55 КоАП (обязательные способы идентификации) | С    | С   | решение владельца; варианты в `docs/legal-checklist.md`                                                                        | владелец      | открыт                 |
| R-09 | Данные граждан РФ хранятся вне РФ (локализация, трансграничная передача)                     | С    | В   | раскрыто в Политике; решение владельца до публичного запуска                                                                   | владелец      | открыт                 |
| R-10 | Согласие подписью под кнопкой оспоримее отдельной отметки                                    | С    | С   | журнал согласий с версией и временем; возврат отметок — правка формы и маршрута входа                                          | владелец      | принят владельцем      |
| R-11 | Публичный псевдоним все же позволяет установить личность                                     | Н    | С   | правила псевдонима, запрет совпадения с данными GitHub, предупреждение; согласие на распространение снято владельцем (ADR-076) | владелец      | принят владельцем      |
| R-12 | Утечка секрета (service role, токен поставщика, секрет расписания)                           | Н    | В   | секреты только в Vercel/Vault; запрет `NEXT_PUBLIC_*` для секретов; очистка логов; проверка логов; ротация по runbook          | разработка    | закрыт мерой           |
| R-13 | Превышение лимитов бесплатных тарифов при росте                                              | Н    | С   | кеш публичных ответов, замеры; лимиты чтения — после облачных измерений                                                        | разработка    | наблюдение             |
| R-14 | Ограничение функции Vercel 60 с при долгом расчете                                           | Н    | С   | пачка до 50 рынков за запуск, таймаут поставщика 10 с, остаток — в следующем запуске                                           | разработка    | закрыт мерой           |

## Развитие после MVP

Уведомления о расчете в реальном времени (в пределах квот), избранные команды, лиги друзей, дополнительные
рынки, экран модерации псевдонимов для администратора, автоматическая еженедельная проверка формата поставщика,
smoke-проверка production после каждого деплоя (см. `docs/testing-strategy.md`).
