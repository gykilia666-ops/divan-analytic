# Сценарий демонстрации (5–7 минут)

Порядок из docs/requirements.md §23. Перед показом: войти на https://divan-analytic.vercel.app, открыть вкладку GitHub
Actions и локально — терминал с проектом.

1. **Реальные матчи и честная свежесть.** `/matches`: по умолчанию «Предстоящие», время в часовом поясе
   браузера, отметка «Последнее обновление». Пояснить: бесплатный поставщик с задержкой, прием закрывается
   за 5 минут до начала и при данных старше часа — по часам базы, а не браузера.
2. **Demo без ключей.** Локально `npm run dev` в режиме demo: тот же интерфейс на вымышленных клубах, демо-рейтинг
   с пометкой. Показать, что demo воспроизводим без единого секрета.
3. **Прогноз и журнал.** Страница матча → исход, сумма → «Подтвердить». `/my/wallet`: баланс и запись
   «Списание за прогноз». Объяснить: одна транзакция в БД, баланс = сумма журнала, повтор с тем же ключом
   не списывает второй раз.
4. **Расчет.** Локально `npm run db:test` — файл `07_settlement`: подтверждение итога вторым наблюдением,
   выигрыш/проигрыш/возврат, повторный расчет без двойной выплаты, изменение итога после расчета → пауза.
   На проде: `/my/bets` после завершения матча, `/my/stats`, `/leaderboard`.
5. **Конкурентность.** `npm run test:integration`: 20 параллельных прогнозов при балансе 1000 → принято ровно 6;
   10 параллельных расчетов → одна выплата; устаревший исполнитель получает LEASE_LOST.
6. **Эксплуатация и CI.** `/admin`: последний успех, запросы к поставщику, очередь расчета с причиной по
   каждому матчу. GitHub Actions: зеленые прогоны каждого этапа. `docs/measurements.md` — фактические замеры.

Главное, что стоит проговорить: надежные транзакции, повторно безопасный расчет, контролируемая интеграция
с внешним API и воспроизводимость — а не количество библиотек.
