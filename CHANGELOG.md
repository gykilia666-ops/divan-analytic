# История изменений

Проект развивался по этапам из [требований](docs/requirements.md) (§17). Этап считался завершенным только
после полной локальной проверки (`scripts/verify.ps1`: формат, линтер, типы, unit, сброс БД, pgTAP,
интеграция, build, e2e) и зеленого GitHub Actions. Числа тестов — на момент закрытия этапа. Решения — в
[`docs/adr/`](docs/adr/README.md).

## [Не выпущено] — этап 11. Релиз и портфолио (в работе)

Production: https://divan-analytic.vercel.app (Vercel `lhr1`, Supabase `eu-west-2`).

### Добавлено

- Облачный Supabase (миграции через `db push`), production GitHub OAuth, синхронизация и расчет по расписанию
  каждые 15 минут: pg_cron + pg_net, адрес и секрет в Vault ([ADR-047](docs/adr/ADR-047.md)).
- Псевдонимы: игрок придумывает имя сам и один раз, уникальность — индексом БД, совпадение с данными GitHub
  запрещено; профиль, кошелек и стартовые 10 000 монет создаются только при выборе псевдонима; без псевдонима
  прогноз не принимается ([ADR-069…075](docs/adr/README.md)).
- Пользовательское соглашение, политика ПДн, согласие на обработку ПДн, журнал согласий; вход закрыт, пока не
  заданы данные оператора ([ADR-065…068](docs/adr/ADR-065.md), [ADR-071](docs/adr/ADR-071.md),
  [ADR-076](docs/adr/ADR-076.md), [ADR-077](docs/adr/ADR-077.md)).
- Удаление аккаунта самим пользователем: обезличивание без стирания журнала денег
  ([ADR-061](docs/adr/ADR-061.md)).
- Тема «День / Ночь», шрифт логотипа, фон с параллаксом, плашка режима только в demo
  ([ADR-062…064](docs/adr/ADR-062.md)).
- e2e connected: полный путь на локальном Supabase — вход, псевдоним, прогноз (двойной клик = одно списание),
  повтор, расчет, статистика, удаление аккаунта; тесты HTTP-слоя всех изменяющих маршрутов.
- Документация: README, выпуск, runbook, сценарий показа, стратегия тестирования, справочник API, пакет
  аналитической документации [`docs/analysis/`](docs/analysis/README.md).

### Изменено

- Регион функций Vercel — `lhr1`, рядом с базой; GitHub Actions на actions v5; e2e connected в CI.
- Каталог матчей по умолчанию показывает «Предстоящие» ([ADR-078](docs/adr/ADR-078.md)).
- Требования, решения и история изменений разнесены по `docs/requirements.md`, `docs/adr/` и этому файлу. В уже
  примененных миграциях поменялись только ссылки в комментариях, SQL не менялся.

### Проверено

GitHub Actions #16 на `7c4410b`: unit 278, pgTAP ~425, интеграция 16, e2e demo 154, e2e connected 5.
В production проверены вход через GitHub, синхронизация по расписанию (`job_runs` — OK) и прогноз.

### Осталось

Данные оператора в Vercel и повторный деплой (до этого вход закрыт), ручной проход «вход → псевдоним →
прогноз» на production, облачные замеры, скриншоты.

## Этап 10. Hardening и измерения — 2026-11-05

- CSP с nonce на каждый ответ, `frame-ancestors 'none'` ([ADR-056](docs/adr/ADR-056.md)).
- Очистка логов от токенов, cookie и почты в одном месте; проверка значений секретов в логах локальных серверов
  ([ADR-058](docs/adr/ADR-058.md)).
- Ручной запуск синхронизации — не чаще раза в 5 минут ([ADR-057](docs/adr/ADR-057.md)), дополнительные индексы.
- Доступность: axe WCAG 2.1 A/AA на ключевых страницах, desktop и 360 px.
- Скрипт измерений: функции БД под ролями, HTTP p50/p95, холодный старт, мобильный LCP
  ([ADR-060](docs/adr/ADR-060.md), [`docs/measurements.md`](docs/measurements.md)).

Проверено: pgTAP 314, интеграция 12, unit 202, e2e 104, `npm audit` — 0 уязвимостей, секретов в логах нет;
GitHub Actions #13 на `b37f64a`. Облачные измерения перенесены на этап 11.
